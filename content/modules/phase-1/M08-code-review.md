# M08 · 代码审查实战

**对应天数**：Day 18–20 | **阶段**：Phase 1

## 1. 项目目标
用审查清单系统审 M03–M07 全部代码；故意保留 3 个 bug，练习发现与修复。

## 2. 会学到什么
- 结构化 code review 流程
- 安全/正确性/可维护三维审查
- 把审查结论写成 lessons_learned

## 3. AI 负责什么
- 扮演「挑刺审查员」找问题
- 修复你指出的 issue 并解释根因
- 生成审查报告 Markdown

## 4. 人需要理解什么
审查不是挑刺，是 **交付前质检**；你是厂长，AI 是工人。

## 5. 必须掌握的代码理解点
- [ ] 能对照 checklist 逐项打勾
- [ ] 能判断「必须改」vs「可以以后改」

## 6. 必须掌握的工程思维
- **Trust but verify**：AI 代码默认有待审
- **小步修复**：一次修一类问题

## 7. 推荐提问方式
```
你是严格的 code reviewer。审查以下项目（M03-M07）。
使用附件 checklist，输出：Critical / Major / Minor 分级列表。
不要直接改代码，先出报告。
```

## 8. 常见 AI 错误
| 错误 | 表现 | 你怎么发现 |
|------|------|------------|
| 审查放水 | 说通过但有硬编码 key | 用 [审查清单](../../templates/code-review-checklist.md) 逐项勾时漏掉关键项 |
| 过度重构 | 审查变重写 | diff 显示改了文件一半以上的行数 |

## 9. 验收标准
- [ ] 完整审查报告 1 份
- [ ] 修复全部 Critical
- [ ] 沉淀 ≥5 条 lessons_learned

## 10. 今日作业与延伸
**作业**：整理个人 prompts 库 ≥10 条。**延伸**：让第二 AI 交叉审查。
