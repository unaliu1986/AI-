# M03 · 文件监听与自动整理

**对应天数**：Day 5–7  
**阶段**：Phase 1  
**关联项目**：[P01 文件夹管家](../../projects/P01-folder-butler.md)

---

## 1. 项目目标

监听 `Downloads`（或指定 inbox 文件夹），新文件出现时按扩展名自动移动到子文件夹，并记录日志。

---

## 2. 会学到什么

- 文件系统事件监听（watchdog 库）
- 移动 vs 复制；冲突重命名策略
- 长期运行脚本的启停方式

---

## 3. AI 负责什么

- 实现 `FileHandler` 子类与 `Observer` 配置
- 扩展名 → 目标文件夹映射表
- 日志与异常处理骨架

---

## 4. 人需要理解什么

| 概念 | 通俗解释 |
|------|----------|
| **事件驱动** | 不是定时去查，而是「有新文件了通知我」 |
| **Handler** | 收到通知后具体干活的逻辑 |
| **阻塞运行** | 脚本一直开着，像保安值班 |

---

## 5. 必须掌握的代码理解点

- [ ] `on_created` / `on_moved` 何时触发
- [ ] `shutil.move` 与 `shutil.copy2` 区别
- [ ] 配置 dict：`{".pdf": "docs", ".jpg": "images"}`

---

## 6. 必须掌握的工程思维

- **幂等**：同一文件触发两次不能炸
- **可配置**：规则放 YAML/JSON，不改代码能改行为
- **可观测**：每次移动写 log，方便事后查

---

## 7. 推荐提问方式

```
用 Python watchdog 监听 ./inbox：
- .pdf → ./sorted/docs/
- .jpg/.png → ./sorted/images/
- 其他 → ./sorted/other/

- 用 logging 模块，日志到 logs/watcher.log

请先给架构说明（3 句话），再写代码。
Windows 环境。
```

---

## 8. 常见 AI 错误

| 错误 | 表现 | 你怎么发现 |
|------|------|------|
| 移动进行中文件 | 浏览器下载未完成就移动 | 文件大小为 0 或损坏 |
| 递归监听风暴 | 移动到监听目录内又触发 | CPU 飙高 |
| 忽略隐藏文件 | `.tmp` 被移动 | 临时文件污染 sorted |
