# M02 · 读懂 AI 生成的代码

**对应天数**：Day 3–4  
**阶段**：Phase 1

---

## 1. 项目目标

对 AI 生成的 3 个小脚本做「逐行标注」：标注懂/不懂/需验证，并完成一次正式代码审查。

---

## 2. 会学到什么

- 读 Python 代码的最小词汇表（不必会写）
- 用审查清单发现 AI 的坑
- 让 AI 「用小学生能懂的话」解释任意一行

---

## 3. AI 负责什么

- 生成 3 个难度递增的练习脚本
- 逐行解释你标记「不懂」的行
- 根据审查清单自动自查并修复

---

## 4. 人需要理解什么

| 概念 | 通俗解释 |
|------|----------|
| **变量** | 贴标签的盒子，装着数据 |
| **函数 def** | 一段可重复调用的迷你程序 |
| **循环 for** | 对列表里每一项做同样的事 |
| **条件 if** | 满足条件才执行 |
| **try/except** | 出错了走备用路线，不让程序直接崩溃 |

---

## 5. 必须掌握的代码理解点

- [ ] 能说出 `def foo(x): return x+1` 的输入输出
- [ ] 能识别「这段在读文件 / 调网络 / 写数据库」
- [ ] 看到 `requests.get` 知道是在访问网页/API
- [ ] 看到硬编码字符串 `'sk-xxxxx'` 知道要拒绝

---

## 6. 必须掌握的工程思维

- **审查先于运行**：陌生脚本先扫一眼安全项
- **不懂就追问**：一行不懂不要整段跳过
- **diff 思维**：改代码前知道「改前改后差什么」

---

## 7. 推荐提问方式

```
下面这段代码，请：
1. 用不超过 2 句话说明整体在干什么
2. 逐行注释（中文）
3. 标出 3 个潜在 bug 或坏味道
4. 不要重写，先审查

（粘贴代码）
```

---

## 8. 常见 AI 错误

| 错误 | 表现 | 你怎么发现 |
|------|------|----------|
| 过度解释 | 讲语法课而非业务逻辑 | 要求「只解释这行在业务上干什么」 |
| 掩盖 bug | 说「没问题」但有路径硬编码 | 对照审查清单 |
| 重写过度 | 你只想懂一行，它重写整个文件 | Prompt 加「不要改代码，只解释」 |
