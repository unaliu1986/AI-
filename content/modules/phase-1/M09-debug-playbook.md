# M09 · Debug  playbook

**对应天数**：Day 22–24 | **阶段**：Phase 1

## 1. 项目目标
建立个人 Debug 流程：读 traceback → 最小复现 → AI 辅助 → 验证修复。

## 2. 会学到什么
- Python traceback 从上到下读
- 最小复现（输入越少越好）
- 二分法定位：注释一半代码找问题

## 3. AI 负责什么
- 解释 traceback 每一帧
- 建议 3 个可能原因与验证步骤
- 修复后写回归测试思路

## 4. 人需要理解什么
| 概念 | 解释 |
|------|------|
| traceback | 错误发生时的调用链 |
| 复现 | 用最小步骤让 bug 再出现一次 |

## 5. 必须掌握的代码理解点
- [ ] 最后一行是真正的异常类型与消息
- [ ] 往上找「你的项目文件」而非库内部

## 6. 必须掌握的工程思维
- **先复现再修**：没复现就在猜
- **修完要验证**：同一输入跑两次结果一致

## 7. 推荐提问方式
```
报错如下：（粘贴完整 traceback）
相关代码：（粘贴 20 行）
请：
1. 用中文解释错误原因（不超过 5 句）
2. 给出验证假设的最小步骤
3. 再给修复 diff，不要重写整个文件
```

## 8. 常见 AI 错误
| 错误 | 表现 | 你怎么发现 |
|------|------|------------|
| 猜错根因 | 改完仍报错 | 改完后同一个 traceback 仍然出现 |
| 隐藏真实问题 | 加 try/except 吞错 | 看起来运行成功但输出为空或不全 |

## 9. 验收标准
- [ ] 独立修复 1 个「路径错误」bug
- [ ] 写 Debug 日记 1 篇（现象→原因→解法）
